# MES 实时数据工具与 Agent 合同

> 版本：1.0（2026-07-16）  
> 用途：指导 Agent 何时检索 RAG、何时读取真实 MES 数据，以及读取后的安全处理方式。

## 1. P0 工单链只读工具

以下工具通过 FastAPI 的受控网关转发 JWT 到 Spring Boot；它们读取的是当前业务事实，不写业务数据：

| 工具语义 | 必要参数 | 返回事实 | 适用问题 |
|---|---|---|---|
| 工单流程快照 | `work_order_no` | 从订单到入库的当前流程 | “当前下一步是什么？” |
| 齐套快照 | `work_order_id` | BOM 齐套、合格可用库存、欠料明细 | “为什么不能排产/领料？” |
| 生产任务快照 | `work_order_id` | 工序、工位、计划/完成数量 | “任务做到哪一步？” |
| 派工快照 | `work_order_id` | 现场派工；操作工仅可见本人派工 | “谁被派到这个任务？” |
| 工单追溯快照 | `work_order_no` | 领料、报工、质量、入库、批次、SN | “该工单用了哪些批次？” |
| 知识检索 | `query`，可附角色/工厂/产品/工序/状态过滤 | 已审核 SOP 与规则及引用 | “这个状态按规则该怎么处理？” |

输入中的工单编号需要格式校验，工单 ID 必须为正整数；工具输出应带 `trace_id` 和查询时间。任何实时值都不得被缓存为共享知识或模型记忆。

## 2. 智能排产写入合同

只有以下受控领域动作可以造成排产主链业务写入：

| 动作 | 前置条件 | 领域结果 |
|---|---|---|
| 订单确认与工单生成 | 用户确认、订单/产品复读校验、角色满足权限、无重复工单 | 更新订单确认状态，创建关联工单 |
| 原子排产 | BOM/路线/齐套分析通过，风险为 LOW | 锁料、生成任务、排产、派工同步由已有事务完成 |
| 生产领料执行 | 工单满足既有状态和数量校验、调用者具备权限 | 生成/执行领料出库，写入物料消耗追溯并推进后续现场作业条件 |

Agent 只能调用这些已存在的 Spring Boot 边界；不能绕过它们直接写 `customer_order`、`work_order`、`production_task`、`dispatch_task`、库存或消耗记录。

## 3. 质量与报告的数据合同

- 日常质量分析读取质量概览，以及可选的工单质量追溯；没有质量写入权限。
- 质量报告每次新取报告快照，包含趋势、待检、缺陷和风险计算所需的真实数据；这些快照用于该报告的可追溯导出。
- 报告审计数据与业务质量数据不同：前者记录报告、会话归属、快照与导出状态，后者仍以 `fan_mes` 的质量业务表和领域服务为权威。
- 报告可以在规则结论形成后立即 `READY`；外部模型补充说明不能阻断导出功能。

## 4. 数据最小化与可解释输出

Agent 向模型发送数据时遵守最小化原则：只提交回答问题所需的压缩事实、明确统计窗口和规则引用。输出中应标明哪些是“实时事实”、哪些是“规则依据”、哪些是“模型建议”。

当关键字段缺失、权限不足、接口失败或返回不一致时，正确行为是停止相应结论、报告缺失项并建议下一步查询/人工确认；不得以猜测填补业务数据。

## 5. 适合进入后续 LangGraph 的节点合同

每个候选节点至少定义：触发意图、输入 ID/过滤条件、实时读工具、RAG 查询词、是否允许写入、确认节点、输出事实结构、失败状态和可视化卡片名称。这样可在不破坏既有 MES 事务的前提下，把独立业务 Agent 接入主协调图。
