# 质量报告 Agent：图文报告与 Word 导出运行说明

> 版本：1.0（2026-07-16）  
> 适用角色：`MANAGER`、`PROD_SUPERVISOR`、`QUALITY_INSPECTOR`、`TESTER`。  
> 触发示例：“帮我生成质量分析报告”“整理一份今日质量报告”“导出质量报表”。

## 1. 这是质量分析后的独立续接流程

质量报告请求应优先匹配 `QualityReportWorkflow`，而非回落为普通质量分析。它使用新的 `report_id` 和新的实时质量快照，形成可审计、可导出的报告；不会把上一轮聊天内容或旧统计数字直接当作报告数据。

流程只读质量业务事实，但会将报告快照与导出状态写入 Agent 报告审计存储。它不修改检验、缺陷、放行、工单或库存等业务记录。

## 2. 报告生成步骤

| 顺序 | 责任者 | 内容 | 关键边界 |
|---:|---|---|---|
| 1 | `IntentRoutingAgent` | 确认质量报告意图与统计窗口 | 外部模型仅作意图解释 |
| 2 | `QualityManagementAgent` | 读取最近窗口内的实时质量报告快照 | 质量报告 GET 门面；读取失败即停止 |
| 3 | `QualityReportAgent` | 以确定性规则核验待检、合格率、缺陷与风险 | 不由模型篡改指标 |
| 4 | `QualityReportAgent` | 调用本地 Qwen3-0.6B 解读趋势、缺陷优先级和待处置项 | 输入为压缩事实包 |
| 5 | `QualityReportAgent` | 生成执行摘要、图、表、风险与行动建议 | 图表和表格均来自本次快照 |
| 6 | `MainAgent` | 可选外部模型补充解读 | 仅丰富文本，不能阻塞交付 |
| 7 | 导出服务 | 用户确认后生成 Word | 以已保存的 report snapshot 为唯一事实来源 |

## 3. 图文报告与导出可用性

报告会生成趋势、缺陷 TOP、缺陷等级分布、待检队列等图表以及对应明细表。先由确定性规则生成可交付的“风险与行动建议”，再把报告状态更新为 `READY` 并推送“是否需要导出 Word？”。

外部模型补充解读是可选增强：即使第三方模型缓慢、超时或不可用，报告仍应保持可导出，不能让用户被无内容的等待态卡住。后续补充解读成功时可更新报告快照；已导出的报告保留其当时的事实版本。

## 4. Word 导出规范

Word 导出通过 Agent 报告导出接口转发到 Spring Boot 的报告服务。导出文件使用报告快照中的图、文、表：

- 标题和章节标题使用黑体；正文和表格正文使用宋体；
- 图表居中、单行展示、尺寸适中，不挤压或跨越页面边界；
- 使用 A4 页面及统一页边距；
- 图表、表格和结论按报告章节顺序排列；
- 导出前必须确认当前用户对该 `report_id` 具有访问范围。

## 5. 报告事实边界

报告里的统计值、图表和风险触发依据是动态事实，存在 Agent 报告审计快照中，不得写入共享 Qdrant 知识库。Qdrant 只保存报告生成原则、质量门禁、角色范围和“实时事实优先”的规则。

若实时质量报告快照无法取得或无法安全保存，流程必须停止并提示无法生成可导出的报告；禁止以模型编造的“示例报告”替代真实报告。

## 6. 适合回答的问题

- “质量报告包含哪些指标？”：说明图、表、风险和行动建议结构。
- “为什么图表生成后可以先导出？”：解释规则结论优先、外部模型仅补充。
- “报告是否会修改质检数据？”：不会；它读取实时数据并写入报告审计快照。
- “为什么导出的数字和上次不同？”：每次报告读取新的质量快照，时间窗口和实时业务数据可能变化。
