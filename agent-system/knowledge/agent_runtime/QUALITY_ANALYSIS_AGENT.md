# 质量总 Agent：今日质量分析运行说明

> 版本：1.0（2026-07-16）  
> 适用角色：`MANAGER`、`PROD_SUPERVISOR`、`QUALITY_INSPECTOR`、`TESTER`。  
> 范围：用户提出“帮我分析今天的质量情况”“今日质量概览”“质量积压/缺陷风险”等问题时的只读分析流程。

## 1. 触发与总原则

质量分析请求需要同时具有质量语义（质量、质检、不良、缺陷、检验、IQC、IPQC、PQC、OQC、RQC）和分析语义（今天、情况、分析、概览、积压、风险、趋势等）。

`QualityWorkflow` 是只读工作流：它不提交检验结论、不修改缺陷、不放行产品、不改变工单状态。它输出的建议仅辅助质量人员判断，最终质量门禁仍由既有质量领域服务与人员确认。

## 2. 五段式事实分析流程

| 顺序 | 输出卡片/责任者 | 工作内容 | 数据或模型来源 |
|---:|---|---|---|
| 1 | `IntentRoutingAgent`：质量分析意图识别 | 解释请求范围，检索质量 SOP | 外部意图模型 + 角色范围 RAG |
| 2 | `QualityManagementAgent`：实时质量事实采集 | 读取待检、趋势、缺陷和处置事实 | 质量只读门面，最终来自 `fan_mes` |
| 3 | `QualityManagementAgent`：质量风险规则检核 | 对积压、通过率、缺陷等级执行确定性规则 | 运行时事实包 + 规则代码 |
| 4 | `QualityManagementAgent`：本地 Qwen3-0.6B 质量微分析 | 对压缩事实进行短分析，解释异常优先级 | 本地 `Qwen3-0.6B`；不拥有写权 |
| 5 | `MainAgent`：质量总体分析与风险建议 | 基于已完成事实和本地检核给出结论 | 外部模型 + 已审核 RAG；失败时规则回退 |

流式输出按“一个节点一个卡片”完成：节点开始、文本增量、节点完成，不应拆成大量单字空卡片。等待模型首个有效片段时可展示等待反馈，但不能伪造内容。

## 3. 实时质量事实与正确解释

质量分析通过 `QualityManagementAgent` 的 GET 白名单读取质量概览；若带工单上下文，还会读取该工单的质量追溯快照。实时事实可能包含待检队列、检验完成与合格率、趋势、缺陷等级/类型、待处置风险等。

这些字段每次调用都可能不同。因此：

- “待检多少”“合格率多少”“近 7 天 CR 缺陷多少”必须以本次读到的事实为准。
- RAG 仅解释 IQC/IPQC/OQC/RQC 的流程、质量门禁和处置原则，不能保存或复述旧的数字。
- 读失败时应停止模型分析并提示质量只读门面不可用，禁止输出演示质量结论。

## 4. 模型输出的限制

本地 Qwen3-0.6B 用于质量细项微分析，外部模型用于最终自然语言综述。两者必须仅依据传入的压缩事实、确定性风险结果及 RAG 规则进行解释。

模型建议应包含：风险依据、优先核查动作、需要谁跟进；但不得：

- 擅自修改检验结果、缺陷等级、放行状态或工单状态；
- 把历史检索片段当作今天的真实数据；
- 在实时事实读取失败时给出肯定性的质量结论；
- 建议绕过质量门禁或以语言结论替代检验记录。

## 5. 追问与报告衔接

完成质量分析后，用户可继续请求“生成质量分析报告”。该请求应优先进入独立的质量报告续接工作流，而不是再次执行五段式日常分析。报告会重新读取一份新鲜的质量快照，避免把先前对话中的数字直接复用为报告事实。

## 6. 推荐回答结构

1. 说明统计窗口和事实来源；
2. 给出待检、通过率、缺陷/趋势等核心事实；
3. 说明确定性风险规则触发情况；
4. 列出按优先级排序的核查或处置建议；
5. 标明建议仅供辅助决策，并提示必要的实时复核与质量人员确认。
