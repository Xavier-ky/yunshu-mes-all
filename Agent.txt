核心架构要求：

系统采用多 Agent 协同架构。

1. MainAgent / SupervisorAgent

职责：
- 接收用户请求
- 识别用户意图
- 判断涉及哪个业务板块
- 拆解任务
- 选择一个或多个子 Agent
- 协调子 Agent 执行
- 汇总各子 Agent 结果
- 控制权限和确认流程
- 生成最终回答

限制：
- MainAgent 不直接查数据库
- MainAgent 不直接调用 Spring Boot 业务接口
- MainAgent 不直接执行工具
- MainAgent 只能通过子 Agent 和 Tool Registry 完成任务
- MainAgent 不能绕过子 Agent 权限

2. 子 Agent 设计

请按九大业务板块设计子 Agent：

- OverviewAgent：系统总览 Agent
- ScheduleAgent：计划调度 Agent
- WarehouseAgent：仓储管理 Agent
- ProductionAgent：生产管理 Agent
- QualityAgent：质量管理 Agent
- AndonAgent：安灯中心 Agent
- EquipmentAgent：设备管理 Agent
- SystemAgent：系统管理 Agent
- AnalyticsAgent：分析集成 Agent

每个子 Agent 必须有明确职责、权限边界和工具范围。

子 Agent 基本结构必须包含：

- agent_name
- business_module
- description
- allowed_tools
- allowed_api_paths
- read_permissions
- write_permissions
- require_confirmation_actions
- risk_level
- handle_task()

权限原则：

- 查询类操作可以自动执行。
- 写入、修改、删除、关闭、发布、提交、确认、入库、出库、发料、报工、质检提交、状态流转都必须先生成确认卡片。
- SystemAgent 第一版默认只读，不允许修改用户、角色、权限。
- AnalyticsAgent 第一版只读，只做统计和分析。
- Trace、日志、确认记录必须可查看。
- 子 Agent 不能调用权限范围外的工具。
- 模型不能直接生成 SQL 操作业务库。
- 即使后续增加数据库访问，也必须通过受控 DataAccess 或 SpringBootClient，并经过权限白名单校验。

九大子 Agent 权限建议：

OverviewAgent：
- 可读：系统总览、今日生产、待办、异常数量、设备状态、质量概览
- 可写：默认无
- 主要用途：汇总系统运行情况

ScheduleAgent：
- 可读：生产计划、排产结果、产线能力、工单优先级、物料齐套状态
- 可写：排产建议保存、计划调整申请
- 高风险：下达计划、调整工单优先级、修改排产

WarehouseAgent：
- 可读：库存、批次、齐套、发料、入库、出库记录
- 可写：发料确认申请、库存调整申请
- 高风险：确认发料、库存调整、入库确认、出库确认

ProductionAgent：
- 可读：生产进度、工位作业、报工记录、条码绑定、产线状态
- 可写：提交报工申请、工位操作记录申请
- 高风险：提交报工、修改产量、变更生产状态

QualityAgent：
- 可读：质检任务、质检记录、不良统计、返修记录
- 可写：质检结果提交申请、返修单创建申请
- 高风险：提交质检结果、判定不良、创建返修单

AndonAgent：
- 可读：安灯事件、异常任务、处理记录、异常分类
- 可写：创建安灯、分派任务、关闭安灯申请
- 高风险：关闭安灯、分派责任人、修改异常等级

EquipmentAgent：
- 可读：设备状态、点检记录、保养计划、维修记录
- 可写：创建设备维修申请、保养确认申请
- 高风险：设备停机、维修完成确认、保养完成确认

SystemAgent：
- 可读：用户、角色、权限、菜单、系统配置
- 可写：第一版禁止
- 高风险：所有系统管理写入操作

AnalyticsAgent：
- 可读：生产报表、质量报表、设备报表、安灯报表、库存报表
- 可写：报表生成记录
- 高风险：默认无
- 主要用途：跨模块分析、趋势总结、管理建议

必须实现的核心模块：

1. Agent Registry
- 统一注册 MainAgent 和所有子 Agent
- 根据业务板块和权限选择 Agent

2. Tool Registry
- 统一注册工具
- 工具必须声明所属模块、动作类型、风险等级、是否需要确认

3. Permission Guard
- 校验子 Agent 是否有权限调用某工具
- 校验当前用户角色是否允许该操作
- 阻止 MainAgent 或子 Agent 越权调用

4. LLM Adapter
- BaseLLM
- MockLLM
- OpenAICompatibleLLM
- OllamaAdapter，占位即可
- 第一版必须支持 MockLLM，无 API Key 也能运行

5. SpringBootClient
- 统一封装对 Java Spring Boot 的调用
- 第一版 ENABLE_MOCK_TOOLS=true，返回 mock 数据
- 后续 ENABLE_MOCK_TOOLS=false 时切换真实接口
- 工具中不要散落 http 请求

6. Confirmation 机制
- 所有写入类动作必须生成确认卡片
- 用户确认后才执行真实动作
- 用户取消后记录 trace 并终止动作

确认卡片至少包含：

- confirmation_id
- 发起 Agent
- 所属业务板块
- 操作名称
- 影响对象
- 请求参数
- 风险等级
- 风险说明
- 预期结果

7. Trace 机制
- 前端要展示类似 Codex 的执行步骤
- 至少记录用户输入、MainAgent 判断、选择的子 Agent、每个子 Agent 的任务、工具调用、工具输入输出、确认状态、最终回答
